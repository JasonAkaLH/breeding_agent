# OCR 用法

## 输入优先级

1. 用户在会话中上传的图片、PDF 或扫描件。
2. 用户粘贴的少量可识别文本上下文；这仅用于解释，不替代 OCR 文件。

如果没有上传 artifact，也没有可用文件内容，只问一个关键问题：请用户上传图片/PDF。

## 执行与展示

- 平台执行层负责上传、识别、轮询、结果读取和清理。
- 对用户只呈现一次 OCR 操作的最终结果；不要要求用户手动轮询 job。
- 成功时优先展示 Markdown 文本；用户需要结构化结果时再提供 JSON 摘要。

## 失败处理

失败时读取结构化错误中的 `error`、`error_code`、`stage`、`error_type`、`retriable` 和 `status` 等信息，不要只说“调用失败”。

- HTTP 非成功、远端错误、任务失败/取消/过期等都应保留明确错误码和错误信息。
- 排队、运行中、取消中、结果暂不可用等中间状态不是最终失败；平台执行层会等待到成功、终态失败或超时。
- 大 PDF 或远端处理超时时，说明超时或任务状态，不要假装已经完成。
- 如果服务返回部分诊断，优先告诉用户可操作建议，例如重新上传更清晰文件、缩小 PDF、确认文件可访问。
