认证规则

Authorization header 只放 API token。除登录接口外，所有受保护接口都不接收 username，服务端只通过 token 定位用户。

会话规则

conversation_id 由调用方生成或复用；官方非 GET 路由不在 URL 中携带业务 ID，统一放入 JSON body 或 multipart form。

任务规则

提交消息返回 task_id；任务输出以 SSE 为主，任务摘要、图、等待输入和产物接口用于状态恢复与补充展示。

Skill 软绑定

Slash command 或 API 点名 Skill 时，不直接执行 skill.*；固定提交 main_agent.respond + metadata.soft_skill_binding，由主代理判断答疑、缺参追问或内部执行。

文件下载判定

客户端只把 artifact_type=file 且 download_url=/api/v1/artifacts/{artifact_id}/download 的 artifact 渲染为下载；模型文本中的 sandbox:/mnt/data、file://、/mnt/data 或 outputs/... 不是平台下载链接。

认证方式

当前系统不管理完整用户账户体系，仅维护 username 与当前 token 的映射关系。

登录

POST /api/v1/auth/login 只接收 username。若用户名不存在则创建映射行；无论是否已有映射，都会生成新的当前 access_token 并返回。

登出

POST /api/v1/auth/logout 通过 Authorization token 定位用户，只清空 token 字段，保留 username 记录。

刷新

POST /api/v1/auth/refresh-token 通过当前 token 定位用户，生成新 token 替换旧 token，并返回新 token。

单 token 当前性

同一 username 只允许一个有效 token；旧设备或旧页面持有的 token 会在重新登录、刷新或登出后立即失效。

禁止伪造用户

除登录外，body、query、form、metadata 与 answer_payload 都不应携带用户或 token 字段；这类字段会被拒绝或忽略。

浏览器本地存储

前端可把 access_token 保存在浏览器 localStorage，并为 REST、multipart upload 与 SSE fetch-stream 注入 Authorization header。

推荐调用流程

业务对话台通常按下面顺序串联接口；SSE 是任务输出的主通道。

启动

GET /auth/me 用 Authorization 校验登录态；GET /capabilities 初始化公开能力列表；GET /conversations 恢复历史会话。

对话

可先上传附件，再调用 POST /conversations/chat-messages；conversation_id 放在 body。响应中的 task_id 是后续查询核心。

收尾

SSE 完成后读取 messages 与 artifacts；文件 artifact 用 download_url 或下载接口获取。

给外部系统的完整任务链路

  1. 建立身份：先登录或校验 token。除 POST /api/v1/auth/login 外，不要在任何 body、query、form、metadata 或 answer_payload 中传 username；服务端只信任 Authorization token 解析出的用户。
  2. 准备对话上下文：外部系统可以自己生成并复用 conversation_id。进入页面或恢复工作台时，先读会话列表和消息历史；需要附件时先上传文件，后续只传 upload_id。
  3. 创建任务：用户真正发送一句话时调用 POST /api/v1/conversations/chat-messages。响应里的 status=accepted 只表示任务已接收，不表示执行完成；task_id 是后续订阅、取消、查询图、查询产物和补充输入的主键。
  4. 以 SSE 为主账本：拿到 task_id 后立即订阅 GET /api/v1/tasks/{task_id}/events。前端展示中的节点开始、完成、失败、取消、等待输入、恢复执行和终态都应以 SSE event_type 为准。
  5. interrupt 顺序：只有当 SSE 中收到 node.waiting_for_input 后，才调用 GET /api/v1/tasks/{task_id}/interrupts 拉取结构化问题并渲染补充输入。/graph 的节点状态只能用于排查或恢复展示，不能替代 SSE 触发 interrupt。
  6. 回答并恢复：用户补充信息后调用 POST /api/v1/tasks/interrupts/answer。随后继续订阅同一个任务的 SSE，按 node.ready_to_resume、node.resuming、后续节点事件和任务终态更新 UI。
  7. 终态收尾：收到 task.completed、task.failed 或 task.cancelled 后，任务流结束。完成任务再读取 /messages 同步最终 assistant 文本，读取 /artifacts 渲染可下载产物。

Skill 软绑定提交规则

外部客户端不得直接提交 capability_id=skill.*。用户通过 slash 或 API 点名 Skill 时，应提交 capability_id=main_agent.respond，并在 metadata.soft_skill_binding.capability_id 中放目标 Skill；服务端先让主代理基于公开 profile 判断是回答用法、追问缺参还是内部执行绑定 Skill。

答疑路径会先产生 soft_skill_binding.decision，随后通过 main_agent.output_delta 流式输出，并在完成时持久化最终 assistant 消息；后续追问按普通对话历史带入上一轮请求与答复。执行路径不会把 skill.* 暴露给外部请求方，而是由内部 deterministic replanner 展开到目标 Skill。

  "routing_mode": "force_capability",
  "capability_id": "main_agent.respond",
  "metadata": {
    "soft_skill_binding": {
      "capability_id": "skill.field_design",
      "command": "/field-design"

流式持久化规则

main_agent.output_delta 与 main_agent.reasoning_delta 是实时 transient 事件：只推送给当前 SSE 连接，不写入数据库，也不会在刷新后 replay；reasoning 内容不会持久化。任务成功完成后仅持久化最终 answer / artifact 与 main_agent.output_final 元信息。任务失败、用户停止或中断时不会保存 partial answer，只保留终态与脱敏诊断。SSE 建连要求当前 token 和 task owner；建连后事件循环不再读取 token 表，也不会按每条事件更新 last_used。refresh token、logout 或后续 revoke 会递增 auth_generation，并通过本地缓存 / PostgreSQL LISTEN-NOTIFY 使旧 SSE 关闭；生产 PostgreSQL listener 必须先 LISTEN 再 reconcile，且不健康时 SSE fail-closed 为 auth_generation_unavailable。

错误与状态码

API 使用 HTTP status 表达通用错误；FastAPI 参数校验错误通常为 422。

400 请求错误（Bad Request）

请求语义不合法，例如 scope 值非法、文件内容不符合要求。

401 未认证（Unauthorized）

缺少 Authorization、token 不存在、已被刷新替换或已登出。

404 未找到（Not Found）

会话、任务、上传或产物不存在，或不属于当前用户。注意：上传列表和会话任务列表对不存在的 conversation_id 返回空列表；删除不存在的 upload_id 返回 deleted=false。

409 冲突（Conflict）

提交消息时目标会话已有运行中任务。

422 校验错误（Validation Error）

路径、查询或请求体字段类型不满足 OpenAPI schema，或 payload 携带保留用户 / token 字段。
