# SeedPilot 智慧育种 Agent 路演文案与发布 PPT 大纲

> 用途：客户路演、内部汇报、售前沟通和产品发布会材料。本文把原路演文案和发布式 PPT 结构合在一起，既能当讲稿，也能拆成幻灯片。

## 1. 一句话讲清 SeedPilot

SeedPilot 是面向农业育种场景的专业 Agent 工作入口。它最核心的能力，是把数据查询、田间设计、OCR、群体遗传分析、病害识别、知识导航这类专业能力做成可接入、可治理、可扩展的 Skill 能力包。育种家用自然语言提问，系统再选择合适的能力包去查数据、处理文件、辅助分析和生成结果。

它适合放在企业已有的育种系统旁边使用。原来的数据库、文件和业务系统不用推倒重建，SeedPilot 做的是多加一个好用的智能入口，让团队把已有资料用起来。

更直接一点说，SeedPilot 不是普通的 RAG 问答框。普通 RAG 主要解决“从资料里找答案”的问题；SeedPilot 更强调“专业能力怎么持续接进来”。今天先接数据查询，明天可以接田间设计、OCR、病害识别或群体遗传分析，底座不用重做。

建议发布会主标题：

> SeedPilot 智慧育种 Agent：让育种数据和专业 Skill 能力包进入一个智能工作入口

## 2. 开场讲稿

SeedPilot 是一个面向农业育种场景的智能助手。育种家可以直接用自然语言提问，系统再去完成数据查询、资料整理、分析辅助和结果汇总。

很多育种团队并不缺数据。真正麻烦的是数据太分散，调用太费劲。品种信息在一个系统里，田间记录在另一个系统里，试验结果可能还在表格、图片或历史报告中。

育种家要完成一次判断，通常要先找数据，再筛条件，再做对比，最后整理成报告。这个过程耗时，也依赖熟悉系统的老员工。新人想快速理解材料、性状和历史试验结果，也需要很长时间。

SeedPilot 想减轻的就是这类日常负担。它不替代育种专家的判断，而是把查找、整理、初步分析和文字汇总这些环节变得更快。

PPT 页面建议：

| 页面元素 | 内容 |
|---|---|

| 左侧问题 | 数据分散、操作分散、经验依赖、整理耗时 |
| 右侧变化 | 直接提问、自动查找、连续执行、输出结果 |
| 讲稿落点 | SeedPilot 给育种业务增加一个智能工作入口 |

## 3. 普通 RAG 为什么不够

普通 RAG 的典型做法是：从文档或知识库中检索相关内容，再交给大模型生成回答。这个模式适合制度问答、文档检索和资料摘要。

育种业务不一样。很多问题不是找到一段文字就结束，而是要连接数据库、文件、专业工具、分析工具和可下载产物。比如查一个品种，可能还要筛材料、比较性状、补充试验地点、生成表格，再整理成汇报初稿。

所以 SeedPilot 的目标不是让模型多背一些育种资料，而是让系统能持续接入新的育种能力。每一个能力包都可以有自己的输入、输出、文件处理方式和安全边界。

| 对比项 | 普通 RAG 智能体 | SeedPilot 专业育种 Agent |
|---|---|---|
| 主要动作 | 检索资料后回答 | 选择 Skill 能力包并执行专业任务 |
| 数据来源 | 文档库、向量库 | 数据库、文件、报告、Skill、MCP 和外部工具 |
| 输出形态 | 文本为主 | 文本、表格、报告、HTML、CSV、XLSX、PDF 等产物 |
| 专业扩展 | 加文档、改 prompt | 接入新的 Skill 能力包或 platform-service |
| 业务连续性 | 多数是单轮问答 | 支持多轮上下文、追问、恢复、取消和重试 |
| 安全边界 | 常停留在知识库权限 | 只读查询、SQL Guard、allowlist、artifact 托管和审计 |

发布会可以这样说：

> 普通 RAG 让模型知道更多，SeedPilot 让专业能力接得进来、用得起来。

## 4. SeedPilot 能做什么

### 4.1 用对话完成育种工作

用户不需要记复杂菜单，也不需要知道数据放在哪张表里。可以直接问：

- “帮我查一下这个品种近几年的田间表现。”
- “把这批材料按目标性状做个对比。”
- “根据这些试验结果整理一份总结。”
- “帮我看看高产抗病方向下一步可以怎么分析。”

SeedPilot 会判断该查什么、该调用什么能力，并把结果整理成用户能看懂的回答。

### 4.2 连接已有育种数据

SeedPilot 可以围绕客户现有系统接入数据资源，例如品种信息、性状数据、试验记录、田间记录、文件资料和历史报告。

客户不需要换掉原系统。SeedPilot 把原来分散的数据串起来，让育种人员通过一个入口使用它们。

### 4.3 用 Skill 能力包扩展专业场景

SeedPilot 的能力不是一次写死的。数据查询可以是一个 Skill，田间设计可以是一个 Skill，OCR、病害识别、群体遗传分析、知识导航也可以分别做成能力包。

客户可以先接最常用的能力，比如育种数据查询和报告整理。后面要扩到新作物、新团队方法或新的分析方法，就继续接新的 Skill 能力包，而不是重新做一套系统。

### 4.4 把专业经验沉淀到能力包里

每个 Skill 能力包都可以封装一类相对稳定的专业动作：查数据库、读表格、做田间设计、识别图片、整理报告、调用外部分析工具。

这样做的好处是，专业经验不只停留在某个专家的操作习惯里，也不是散落在 prompt 里，而是可以逐步沉淀成团队可复用的能力。

### 4.5 辅助分析和报告整理

SeedPilot 可以把查询结果、历史材料和分析过程整理成清楚的文字，帮助育种家形成阶段总结、材料对比、试验说明、问题分析和汇报初稿。

这类工作过去经常占用专家大量时间。SeedPilot 可以先完成基础整理，专家再做判断、修订和确认。

### 4.6 信息不完整时主动追问

真实业务里，用户一开始经常说不全条件。SeedPilot 可以继续追问，比如作物类型、目标性状、试验地点、时间范围、文件材料或筛选条件。

这样可以把一个模糊问题逐步变成可执行任务，减少来回沟通和无效查询。

### 4.7 企业级安全治理

育种数据通常是企业核心资产。SeedPilot 支持权限控制、操作审计、数据访问边界和安全治理。

不同角色可以使用不同范围的能力。管理者也可以追踪系统做过什么、查过什么、输出过什么。AI 能力可以进入日常工作，但仍然在可管理的范围内运行。

## 5. 技术亮点怎么讲给客户听

### 5.1 Skill 能力包是主要卖点

SeedPilot 把专业能力抽象成 Capability 和 Skill。数据查询、田间设计、OCR、群体遗传分析、病害识别、知识导航等能力都可以逐步接入。

Planner 看到的是审核后的公开能力，不直接接触脚本路径、数据库连接或底层工具。普通脚本型 Skill、项目级可信 Skill、外部 MCP 工具，都可以按不同安全等级接入。

对外说法：SeedPilot 的专业性不是写在一个 prompt 里，而是沉淀在可治理、可扩展的 Skill 能力包里。

### 5.2 编排能力是底座，不是主卖点

SeedPilot 仍然有主代理编排核心。用户提出问题后，系统会理解任务、选择能力、分发执行、汇总结果，并判断任务是否完成。

但对客户讲的时候，不必把重点放在“任务编排”本身。更好理解的说法是：SeedPilot 先帮客户把一个个专业能力包接进来，再由主代理负责把这些能力用顺。

对外说法：编排能力是后台支撑，真正可被客户感知的是能力包越来越多、场景越来越全。

### 5.3 旁接企业已有系统

SeedPilot 可以围绕客户现有系统接入品种、性状、试验、田间记录、文件资料和历史报告。数据查询能力以只读方式访问企业现有数据库。

对外说法：SeedPilot 不替换原系统，而是把原系统的数据和工具包装成可被 Agent 调用的能力。

### 5.4 文件和产物闭环

用户可以上传表格、报告、图片等业务文件。系统保存文件资源、建立索引，支持历史引用和智能选择。Skill 执行后，可以生成 HTML、CSV、XLSX、PDF、图片等 artifact。

对外说法：SeedPilot 不只输出聊天文本，还能输出业务可用的文件和报告。

### 5.5 主动追问和任务恢复

SeedPilot 支持 interrupt / resume。缺少作物、目标性状、地点、时间范围或文件选择等关键信息时，系统可以追问。用户补充后，系统恢复原任务，而不是重新开一个没有上下文的新任务。

对外说法：模糊问题可以一步步变成可执行任务，更接近育种专家真实的工作方式。

### 5.6 安全治理

数据查询默认只读，并通过 SQL Guard 增加一层保护。Planner 只能选择公开能力，不能任意构造数据库、工具、脚本或服务调用。Skill、MCP 和 artifact 都有受控执行、输出治理和审计边界。

对外说法：SeedPilot 让专业 Skill 能力包进入企业数据环境，但不让大模型自由触碰核心资产。

### 5.7 面向生产的任务体验

SeedPilot 是异步任务驱动的对话式 Agent 服务。前端可以看到任务进度、节点状态、Skill progress 和最终结果。系统支持任务取消、事件 replay、artifact retry、失败自检和 fallback 控制。

对外说法：长任务可观察、可取消、可恢复，更适合企业环境里的复杂分析任务。

## 6. 架构分工

SeedPilot 可以分成六层。客户不需要理解每个技术模块，但这套分层能说明一件事：新的专业能力可以一层层接进来，同时保留安全边界。

### 第一层：访问入口

育种家在这里提问、上传文件、查看结果，也能看到任务执行进度。前端业务对话台、浏览器页面、接口文档、文件上传和消息流都属于这一层。

### 第二层：API 服务层

API 服务层负责接收请求，处理登录、会话、任务、上传和能力列表。用户每一次提问、上传和查看结果，都会先经过这里。

### 第三层：Agent 编排核心

Agent 编排核心负责理解用户想做什么，并选择合适的能力包。比如遇到数据库问题就走数据查询 Skill，遇到材料表就走文件类 Skill，遇到田间设计就走对应的设计能力。

这一层对应 WorkflowRouter、LLM Planner、Scheduler、Memory 等模块。它的价值不是展示复杂内部机制，而是让不同 Skill 能力包能被正确发现、正确调用、正确收束。

### 第四层：能力运行时

能力运行时是真正干活的地方，包括主代理问答、Skill 能力包、MCP 工具能力、文件处理、补槽、中断和取消。

用户问一个育种问题，系统可能会调用数据查询，也可能调用 OCR、田间分析、群体遗传分析或知识导航。条件不够时，它还能继续追问，把问题补完整后再执行。

### 第五层：数据与外部资源

这一层连接状态库、任务消息、文件资料、LLM 能力、MySQL 只读数据和外部工具服务。SeedPilot 正是靠这一层接入企业已有数据和外部分析能力。

### 第六层：Native 和部署底座

这一层负责系统运行、任务存储、沙箱隔离、工具运行和安全内核。客户平时不需要感知它，但它决定系统能不能稳定运行，能不能安全接入企业环境，能不能支撑后续扩展。

安全治理贯穿所有层。认证授权、审计脱敏和访问边界不是某一个单独按钮，而是贯穿用户登录、任务执行、数据访问和结果输出的全过程。

普通 RAG 让模型知道更多，SeedPilot 让专业能力接得进来、用得起来。

### 18. 当前能力基线和边界

可以强调：主代理最小内核、数据查询 Skill 只读 MVP、FastAPI / SSE / cancel / query API、会话记忆、任务状态、事件流和 artifact 基础能力。

需要谨慎表达：不宣称完整长期知识沉淀已经完成；不宣称所有 Rust / MCP enforce 已全部生产完成；不把 SeedPilot 说成替代育种专家。

### 19. 产品路线

第一阶段：育种数据查询、历史报告整理、材料对比分析。

第二阶段：OCR、田间设计、田间分析、群体遗传分析、病害识别、知识导航。

第三阶段：更完整的权限与审计、多实例状态平台、MCP 外部工具生态、Rust runtime 安全与性能底座、Skill Workbench 质量验证闭环。

### 20. 收束页

SeedPilot 让育种团队用自然语言调用专业 Skill 能力包，让企业已有数据、文件和工具被安全地调动起来，也让专家经验和专业方法逐步沉淀为可复用的 Agent 能力。

## 8. 给育种家带来的变化

1. 查数据更快。育种家可以直接提问，不用在多个系统里反复找。
2. 分析更顺。查询、筛选、对比和总结可以连在一个任务里完成。
3. 材料整理更省时间。试验总结、材料对比和汇报初稿可以先由系统生成。
4. 新人上手更容易。新人可以通过对话了解历史数据、材料情况和业务方法。
5. 专家经验更容易复用。历史报告、分析过程和常用判断方式可以逐步沉淀。
6. 数据使用更可控。权限、审计和访问边界让企业更放心地使用 AI。

## 9. 适合的客户场景

SeedPilot 适合已经积累育种数据，但数据使用效率还不够高的团队。比如种业企业、科研育种团队、区域试验管理单位，以及需要把品种、性状、试验和报告统一管理的业务部门。

它也适合从一个小场景开始落地，比如先做育种数据查询、田间报告整理或材料对比分析。等团队用顺了，再扩展到更多作物和更多业务场景。

## 10. 客户价值总结

SeedPilot 的价值不在于多一个聊天窗口，而在于给育种业务增加一个智能工作入口。

对育种家来说，它减少重复查询和整理工作。对团队管理者来说，它提高数据使用效率，让经验和方法更容易沉淀。对企业来说，它可以在不推翻现有系统的前提下，把 AI 能力逐步放进日常育种工作。

- 它能把数据查询、田间设计、OCR、分析工具等做成 Skill 能力包，按场景持续扩展。

- 普通 RAG 让模型知道更多，SeedPilot 让专业能力接得进来、用得起来。
- SeedPilot 不替代育种专家，它把查找、整理、初步分析和报告生成这些环节变得更快。

## 13. 结束话术

SeedPilot 希望做育种家的日常助手：能查数据，能用专业能力包，能整理结果，也能随着客户业务持续扩展。

未来的智慧育种，不只是拥有更多数据，还要让数据更容易被使用，让专家经验更容易传承，让团队把更多时间放在真正的育种判断上。
