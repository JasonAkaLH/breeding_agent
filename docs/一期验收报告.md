# 一期验收报告

> 日期：2026-04-23

## 1. 结论

**结论：一期范围内承诺的“主代理最小内核 + NL2SQL 只读 MVP + FastAPI/SSE/cancel/query API”已完成，当前仓库可判定为一期验收通过。**

## 3. Phase 7 核心验收证据

### 3.1 Happy path
- 文件：`tests/e2e/test_nl2sql_happy_path.py`
- 证明链路：
  1. 提交消息
  2. 背景执行生成 DAG
  3. guard 通过
  4. 只读执行完成
  5. summary / artifact 落地
  6. 前端事件流看到 `task.completed`

### 3.2 Guard blocked
- 文件：`tests/e2e/test_nl2sql_guard_block.py`
- 证明链路：
  1. 通过 deterministic `sql_generator` 生成危险 SQL
  2. `nl2sql.sql_guard_blocked` 写入审计
  3. 任务收敛为 `failed`
  4. 审计中保留 `block_reason` 与 `route_context`

### 3.3 Interrupt / Resume
- 文件：`tests/e2e/test_interrupt_resume_flow.py`
- 证明链路：
  1. 用户问题缺少作物信息，触发 interrupt
  2. 回答补充信息后，原 task 恢复而不是创建新 task
  3. 原链路继续跑通并收敛为 `completed`

### 3.4 Cancel + Late Result Ignored
- 文件：`tests/e2e/test_cancel_late_result_ignored.py`
- 证明链路：
  1. 在 `sql_execute_readonly` 节点运行中发起 cancel
  2. 底层迟到结果返回后，不回写 `completed`
  3. 审计中保留 `task.late_result_discarded`

### 3.5 Observability / Audit
- 文件：`tests/observability/test_audit_jsonl.py`
- 证明链路：
  1. JSONL 中存在 `event_type / task_id / payload`
  2. blocked SQL 路径存在 `block_reason / route_context`
  3. cancel 路径存在 `task.context_terminated`

## 5. 当前已知风险与遗留项

1. 当前 SSE broker 为**单进程内存实现**，适合本地与一期最小闭环，不代表多实例生产方案。
2. cancel 仍采用**语义终止**，不依赖数据库物理 kill。
3. interrupt/resume 当前已具备验收闭环，但公开 API 仍以一期既定最小面为主，没有扩展为完整前端交互产品面。

## 6. 验收结论边界

本报告确认：
- 一期已收口；
- Phase 7 已形成可复核的测试与文档证据；
- 下一步若继续推进，必须基于新专题进入“第二阶段评估输入”，而不是继续在一期范围内扩写代码。
