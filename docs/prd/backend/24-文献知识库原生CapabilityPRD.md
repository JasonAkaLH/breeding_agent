- **编号**：后端专题 PRD 24。
- **日期**：2026-10-15。
- **最近修订**：2026-10-16，仅补充新读取与结果复用、压缩正文载入的约束和验收。
- **状态**：已按实施计划完成仓库接入与自动验收；真实 PostgreSQL 和真实育种文献模型评测待补，尚未整体关闭验收或部署。结果见[实施验证记录](../../superpowers/specs/2026-10-16-literature-knowledge-implementation-evidence.md)。
- **项目与代码基线**：`breeding_agent`，当前 `main` 分支。
- **范围**：原生知识库能力、文献入库与存储、库级共享、会话选库，以及配套管理页面和问答行为。
- **交付口径**：一次完整交付本文范围，不将已确认需求划为简化版和后续增强版。正式团队管理只预留接口，不属于本次功能。

## 1. 背景与目标

用户需要建立可跨会话使用、可分享的个人文献库。每个库有名称和可编辑的描述，模型根据描述选择相关文献库，再阅读库中的 Markdown 索引，选择目标文献，阅读全文并生成答案。

知识库是 Agent 内的独立原生 Capability。它与 Skill、MCP 同级接入统一能力执行机制，具有自己的工具、执行器和结果合同。文献库是该能力管理和读取的资源，创建文献库不等于注册新 Capability。

产品成功标准：

1. 所有者能在页面完成建库、导入、审核、维护和共享。
2. Agent 能完成“按库描述选库 → 读索引选文献 → 读全文 → 回答”的流程。
3. 用户指定文献库后，知识库工具不能越出指定范围。
4. 共享成员能够阅读、导出和问答，不能维护库或再次共享。
5. 正文替换后，系统清除旧正文及受管全文副本；已经输出的答案保持原样。

## 2. 已确认的产品边界

| 决策 | 约束 |
|---|---|
| 规模与输入 | 面向每库几百篇文献，输入为已有 Markdown 全文，支持批量上传。 |
| 技术选型 | 复用现有 Python、FastAPI、Pydantic、SQLAlchemy、模型适配层和 Agent Loop；不引入 LlamaIndex、PageIndex、embedding 模型或向量数据库。 |
| 身份前提 | 沿用现有用户名登录，接受使用者相互信任的环境假设，本专题不扩展认证系统。 |
| 管理入口 | “用户账户设置 → 文献知识库”；管理操作通过页面执行，Agent 只读。 |
| 入库审核 | 自动从全文提取元数据、生成简述；所有者修正并确认后入库，允许批量确认。 |
| 文献身份 | 跨库独立管理；同库按原始文件字节的 SHA-256 判重。 |
| 正文保留 | 只保留当前正文，替换后清除旧正文，不提供历史正文版本。 |
| 共享方式 | 向已有用户授予只读权限，立即生效；预留正式团队共享的授权接口。 |
| 选库模式 | 默认所有可访问库参与；可显式选择多个库，选择在当前会话持续生效。 |
| 运行中修改选择 | 当前提问使用提交时固定的范围，修改从下一次提问生效。 |
| 库失效 | 使用剩余可访问的已选库并提示；全部失效则要求重选，禁止自动扩大范围。 |
| 回答行为 | 文献结论标注出处；证据不足时允许补充通用知识，但需明确区分。 |
| 历史回答 | 输出后就是独立普通聊天消息，与文献生命周期无关。 |

非本次范围：PDF/OCR/网页采集、跨库共用文献记录、共享编辑者、邀请接受流程、团队与团队成员管理、Agent 修改知识库、历史正文归档，以及历史答案复核、重算、失效标注或关联删除。

## 3. 角色与页面入口

### FR-01 文献库管理入口

点击现有“用户账户设置”按钮后，能够进入文献知识库管理。保留现有 MCP 设置入口，将文献库管理作为同一设置区域中的独立功能。

管理界面至少包含“我的文献库”和“共享给我”。所有者可创建、修改库名称和描述、导入文献、审核草稿、维护文献、管理共享及删除文献库。描述允许为空；为空时模型仍能根据库名称识别候选，页面提示补充描述有助于选库。

共享成员只能查看已入库文献和索引、导出 Markdown 正文，并通过 Agent 使用文献库。未确认的导入草稿由所有者管理，不向共享成员或 Agent 暴露。

### FR-02 权限角色

| 操作 | 所有者 | 共享阅读者 |
|---|---|---|
| 查看库名称、描述和已入库文献 | 允许 | 允许 |
| 阅读索引、全文和导出正文 | 允许 | 允许 |
| 通过 Agent 问答 | 允许 | 允许 |
| 修改库名称与描述 | 允许 | 禁止 |
| 导入、审核、修改、替换及删除文献 | 允许 | 禁止 |
| 查看和修改共享名单 | 允许 | 禁止 |
| 删除整个文献库 | 允许 | 禁止 |

所有权由库记录确定，不能通过一条普通共享授权获得。共享角色只有 `reader`，不实现 `editor`。页面隐藏无权操作的控件，后端仍须独立校验每项操作。

## 4. 入库与维护

### FR-03 Markdown 上传与提取

1. 所有者选择目标库，可一次上传一篇或多篇 Markdown。
2. 系统保存原始字节，验证文件可作为 Markdown 文本读取；不让模型改写原始全文。
3. 优先读取文件中已有的元数据，再根据全文补充标题、作者、年份、DOI、关键词和检索简述。
4. 简述应帮助选择文献，涵盖研究对象、研究方法、主要发现和可回答的问题；不得只依赖论文自带摘要生成。
5. 模型不能确认的字段留空，不得编造作者、年份或 DOI。
6. 大文件提取允许分段处理后汇总，必须覆盖完整正文，不能静默只处理开头。

处理过程展示待处理、处理中、待确认或失败等实际状态。提取失败可重试，也允许所有者手工填写必要信息后确认。

### FR-04 人工审核与发布

所有者可查看原始 Markdown、提取字段和简述，逐篇修改，逐篇确认或勾选多篇统一确认。

只有确认成功的文献才是“已入库文献”，进入索引和 Agent 可用范围。确认至少要求非空标题与检索简述；其余书目字段允许为空。批量确认逐篇返回成功或失败状态，失败项不得被标记为已入库。

确认前仍属于导入草稿。所有者可以丢弃草稿，系统清理对应上传文件和处理临时文件。

### FR-05 SHA-256 判重

判重计算对象为上传 Markdown 文件的原始字节，使用完整 SHA-256。计算前不做换行、空格、Unicode、BOM 或文本内容归一化。

- 同一库中，相同 SHA-256 的重复导入返回已有文献；已有处理草稿则复用该草稿，不创建第二份。
- 文件名不同但原始字节相同，仍视为重复。
- 原始字节不同，不因标题、作者或 DOI 相同而自动合并、覆盖。
- 不同库独立保存文献记录与维护状态，任一库更新或删除不影响另一库。
- 同批上传、并发请求或网络重试也必须遵守同库判重约束，不能只在前端检测。
- 判重对象是当前已入库文献和未丢弃的导入草稿；已删除记录或已清理的旧正文哈希不阻止用户重新导入相同文件。文献 ID 与内容 SHA-256 分别表示文献身份和当前内容。

### FR-06 元数据修改与正文替换

所有者可以修改已入库文献的元数据和简述，保存后更新索引。全文替换需要显式选择要替换的文献，再上传新 Markdown，完成提取和人工确认。

待确认的新文件是替换草稿，原正文仍为当前可用内容。确认成功后，该文献 ID 保持不变，当前正文、SHA-256、元数据和索引切换到新内容，并清除旧正文及受管全文副本。数据库修订号只服务并发控制，不代表可访问的历史正文版本。

替换文件与当前正文 SHA-256 相同则不产生新正文；与同库另一条文献相同则提示重复，不自动合并两条文献。并发编辑或确认遇到状态变化时返回明确冲突，不覆盖其他已成功保存的操作。

### FR-07 删除与旧正文清理

删除文献后，该文献立即退出可读取范围，随后清理当前正文、相关草稿、处理临时文件、全文缓存和受管工具副本，并从当前索引移除。删除整个库还应撤销共享，清理该库全部文献和草稿。

正文替换与删除的清理要求：

1. 本组件不创建旧正文历史目录、回收站或 `.bak` 归档。
2. 不能只更新数据库指针而留下可寻址的旧全文；文件系统和受管缓存也应完成清理。
3. 不把正文或逐段原文另存到持久化 AgentItem、Artifact、审计日志、调试日志中，以免形成无法随正文清理的副本。
4. 清理失败时保留可恢复的操作状态，向所有者显示未完成并支持重试；未清理完成不得报告完整成功。
5. 清理只作用于该库该文献的受管数据，不删除其他库的独立副本、用户已经下载的文件或已输出的聊天答案。

更新、删除过程中崩溃或重启后，应能继续完成未完成的发布与清理，不允许恢复为两个可读取正文版本。

## 5. 数据与索引

### FR-08 数据职责

| 对象 | 主要信息 | 职责 |
|---|---|---|
| `KnowledgeLibrary` | 库 ID、所有者、名称、描述、状态、索引修订号 | 库身份与管理权限事实源 |
| `KnowledgeDocument` | 文献 ID、库 ID、书目字段、关键词、简述、当前正文引用、SHA-256、修订号 | 当前已入库文献事实源 |
| `KnowledgeImport` | 库 ID、上传身份、候选 SHA-256、处理状态、待确认字段、可选替换目标 | 入库前草稿与处理状态 |
| `LibraryGrant` | 库 ID、主体类型、主体 ID、只读角色 | 库级共享授权 |
| `ConversationKnowledgeSelection` | 会话 ID、模式、已选库 ID | 会话选库偏好 |

结构化元数据与授权沿用现有 SQLAlchemy 存储体系；原始正文保存为持久化受管 Markdown 文件。文献库生命周期独立于会话，不能通过删除某个会话删除文献库。

正文以稳定的库 ID 和文献 ID 定位，文件名只用于展示；不能将文件名或模型提供的路径作为存储身份。原始字节保持不变，下载结果的 SHA-256 必须与当前记录一致。

### FR-09 Markdown 总索引

每个文献库实际保存一份 `index.md`，包含该库全部已确认、未删除文献的条目。它是根据数据库生成的可重建投影，不是第二个独立编辑的事实源。

库头包含名称、描述、库 ID 和索引修订号。每篇条目包含文献 ID、标题、作者、年份、DOI、关键词、检索简述和当前全文的逻辑引用。缺失字段明确留空或标记未知；条目不包含宿主机绝对路径。

以下仅为格式示意，实际内容由已审核元数据生成：

```markdown
# 文献库名称

library_id: library_001
index_revision: 12

库描述：用户填写的研究范围。

## document_001｜文献标题

- 作者：作者信息
- 年份：年份
- DOI：DOI（如有）
- 关键词：关键词列表
- 全文引用：document_001

### 检索简述

研究对象、研究方法、主要发现及可回答的问题。
```

确认入库、修改元数据、替换正文、删除文献或修改库信息后，均应更新索引。生成采用完整写入后原子发布，不能让读者读到半份文件。索引生成失败需记录待修复状态；读取时校验当前修订号并重建或明确返回失败，不使用过期索引假装最新。

## 6. 共享与团队接口

### FR-10 库级共享

所有者输入已存在于系统中的用户名，后端确认其存在后授予只读权限。用户名只按现有身份规则规范化，不创建虚拟用户、不接受待注册用户名授权。

共享立即生效，文献库出现在接收方“共享给我”列表，无需邀请接受。重复授权应保持幂等。所有者可撤销授权，撤销后禁止新的受管读取和下载；共享阅读者不能转授权。

### FR-11 统一授权接口

授权记录使用可扩展的主体结构：

```text
LibraryGrant(library_id, subject_type, subject_id, role)

LibraryAccessService.list_accessible_libraries(actor)
LibraryAccessService.require_permission(actor, library_id, action)
AccessSubjectResolver.resolve_subjects(actor)
```

当前只接受 `subject_type=user`、`role=reader`，主体 ID 对接现有规范化用户名。所有者权限从库记录取得。

正式团队功能可在同一接口中增加 `team` 主体，并让解析器根据可信成员关系返回该用户所属团队。当前不创建团队表、团队成员功能或可写入但不生效的团队授权。未知主体类型明确拒绝。

API、Agent 工具、索引读取、全文读取和下载统一经过授权服务。文献存储和检索业务不直接依赖团队表；授权缓存必须在共享变化后失效。主体和当前用户来自可信运行上下文，不接受模型自行指定身份。

## 7. 会话选库

### FR-12 自动与指定模式

| 模式 | 页面状态 | 行为 |
|---|---|---|
| `auto` | 全部可访问库 | 个人库和共享库统一作为候选，根据问题和库描述选择相关库。 |
| `selected` | 指定一个或多个库 | 只能列出和读取所选库，不能自行扩大到其他库。 |

对话输入区域提供选库控件，展示“全部可访问库”或已选库名称，支持多选和显式切回自动模式。指定模式须至少选择一个库，清空选择不能在后台静默解释为自动模式。

选库偏好按会话保存，刷新、重连、重新打开该会话后保留；新会话默认自动模式。该偏好不改变任何库的共享权限。

### FR-13 本轮范围固定

提交问题时，服务端根据会话设置与当前权限确定本轮库范围，并以可信上下文绑定到该次任务。模型参数不得扩大范围。

运行中修改选库只影响下一次提问，页面显示“对下一次提问生效”。重试、恢复、工具结果复用仍沿用本轮固定范围，不能重新读取当前会话偏好而发生范围漂移。范围固定不冻结共享权限；实际读取仍校验当时的授权与库状态。

### FR-14 不可用库

指定库中部分库被删除或失去权限时，剔除这些库，使用剩余已选且可访问的库，并明确提示不可用项。所有已选库均不可用时，停止本次知识库问答并要求重新选择，不能回退为自动模式。

自动模式没有任何可访问库时，明确报告没有可用文献库，允许按通用知识回答，并说明回答未得到库内文献支持。

## 8. 原生 Capability 与查询流程

### FR-15 能力接入

定义独立的 `knowledge` 类型与 `knowledge.*` 动作。执行器、输入策略、结果投影和观测分类明确识别该类型，不借用 Skill 名称、Skill bundle 或 MCP Server 包装。

统一 Agent Loop、Invocation 生命周期、取消、重试及恢复机制继续复用。不同文献库不注册独立工具，不另建一个文献问答 Agent Loop。

| 动作 | 模型可提供的主要参数 | 结果 |
|---|---|---|
| `knowledge.list_libraries` | 可选分页游标 | 本轮范围内可访问库的 ID、名称、描述和已入库数量 |
| `knowledge.read_index` | `library_id`、可选分页游标 | 该库 Markdown 索引、修订号、覆盖范围及后续游标 |
| `knowledge.read_document` | `library_id`、`document_id`、可选分页游标 | 指定文献正文及实际书目元数据、SHA-256、读取范围和后续游标 |

工具不接受所有者、共享主体、绝对文件路径或任意存储引用作为模型参数。所有动作都校验本轮范围、实际授权和资源状态。

知识库动作读取可变资源，不直接沿用“能力 ID 与参数相同就复用已完成结果”的规则。每次新调用必须重新校验本轮范围、当前授权和资源状态；索引或正文变化后，不带旧分页游标的相同参数重读应返回当前内容，撤权或删除后相应读取应返回不可用状态，不能返回旧成功结果。重试、恢复也不能绕过上述校验或 FR-13 的固定范围，不能借结果复用恢复旧正文；旧分页游标仍按 FR-17 返回明确的变化状态。

### FR-16 先索引、后全文

Agent 通过库描述选择一个或多个相关库，读取这些库的索引，再选择一篇或多篇文献阅读全文。不能将索引简述当作已经阅读的正文证据。

对文献类问题，提示词应引导模型优先使用知识库。普通无需文献的聊天不必读取所有索引；“全部库参与”表示全部可访问库都是路由候选，不表示把所有库的索引和正文预先注入上下文。

当前指定范围之外的历史文献内容不能作为本轮文献证据。本轮引用应以当前范围内实际读取的正文为依据。历史回答仍作为普通对话保留，不为此建立答案与文献的持久化关联或回溯修改机制。

### FR-17 长索引与长全文

完整 `index.md` 和完整正文始终保存在受管存储中。超过工具结果或模型上下文预算时分段读取，分页只改变传输方式，不改成向量召回，也不能把文件开头当作完整内容。

1. 分页结果携带当前索引修订号或正文 SHA-256、实际覆盖范围、是否末段和后续游标。
2. 各段连续且可核对覆盖，不能因分页漏行、断开 UTF-8 字符或省略正文后仍声称已读完。
3. 只有读取完整索引后，才能声称已检查该库全部索引；未读完应如实说明检索范围不完整。
4. 目标文献按全文阅读；超长正文分段读完，再综合答案。预算不足导致未读完时必须说明阅读不完整，不能声称全文已覆盖。
5. 读取过程中索引或正文发生变化时，旧游标返回明确状态，本轮不能把不同正文拼成一篇；重新读取当前内容或报告读取未完成。
6. 预算按实际将发给模型的内容计数，不能只计算持久化的小型引用。复用现有模型计数、上下文预检和压缩机制；压缩请求也必须按引用载入待压缩的索引或正文实际内容，并按展开后的内容计数，不能只把文献 ID、哈希或读取范围交给压缩模型。压缩摘要应保留与当前问题有关的文献事实及对应文献标识，供后续分段阅读与综合作答使用。

知识库工具持久化结果保存文献身份、内容 SHA-256、范围等引用信息，构造模型请求时按需载入正文。旧引用不得恢复已经清除的正文，也不能将不同 SHA-256 的新正文当成原结果。历史引用不可用只影响后续读取，不触发历史答案标注或修改。

### FR-18 提示词、引用与通用知识

代码提供实际已读文献的标识、标题、作者、年份和 DOI 等字段；提示词负责回答组织与引用表达：

- 文献支持的结论使用 `[1]` 等标号，末尾列出对应文献的标题、作者、年份和 DOI（如有）。
- 只引用本轮实际读过的文献，不编造书目信息。
- 库内没有足够证据时，可以补充通用知识，但明确区分“文献支持”和“通用知识补充”。
- 区分“没有找到足够证据”“读取失败”和“尚未读完”，不能把工具失败表述为文献不存在。
- 库描述、索引、元数据和正文是外部资料，不能改变平台指令、工具权限或本轮选库范围。

引用格式和结论依据通过问答评测验证，不增加答案到文献的运行时依赖。答案输出后就是普通聊天文本，文献更新、删除、撤权均不复核、不重算、不标记失效、不删除既有答案。

## 9. API 与存储实现约束

以下是本专题所需的资源合同；现行 DTO、错误码和示例见 [API 文档](../../api/api-doc.html) 与实施验证记录。管理 API 已在仓库接入，不表示已部署。

| 资源 | 操作与关键约束 |
|---|---|
| `/api/v1/knowledge/libraries` | 查询本人创建及共享给本人的库、创建库；返回有效角色。 |
| `/api/v1/knowledge/libraries/{library_id}` | 查询库、所有者修改名称和描述、删除库。 |
| `.../{library_id}/imports` | 批量上传，查询及修正待确认信息，逐篇或批量确认、丢弃；可显式指定替换目标。 |
| `.../{library_id}/documents` | 查询已入库文献；所有者修改元数据和删除，阅读者不能写入。 |
| `.../{library_id}/documents/{document_id}/content` | 经授权读取或下载当前原始 Markdown，不公开宿主路径。 |
| `.../{library_id}/grants` | 所有者查询、增加、撤销只读共享，校验已有用户并拒绝未知主体类型。 |
| `/api/v1/conversations/{conversation_id}/knowledge-selection` | 会话所有者读取、保存模式与库 ID；服务端验证权限和输入结构。 |

实现须满足：

- 复用 SQLite/PostgreSQL 的共享 SQLAlchemy 模型与仓库模式，新增领域存储合同，不将全文塞进数据库大字段。
- 当前启用的 Agent 执行和恢复路径，包括 Runtime Sidecar 模式，都保持相同的选库范围和只读工具合同；不另建任务控制面。
- 复用安全路径、原子写入和受管文件模式，但不沿用 conversation-scoped 文件的删除生命周期。
- 入库、替换、索引发布、清理和批量确认具备持久状态与幂等性；并发唯一性由后端保障。
- 文件和数据库不可能通过普通数据库事务共同提交时，需要明确恢复顺序，不能用“已写数据库”代替文件发布与清理完成。
- 数据库变更采用现有迁移机制；知识库原始文件不进入 Git 对象、镜像构建上下文或公开静态资源目录。

## 10. 非功能要求

| ID | 要求 |
|---|---|
| NFR-01 | 查询时不重新提取所有论文简述；入库处理异步执行，长处理不阻塞整个管理页面或普通聊天。 |
| NFR-02 | 本专题不提高既有 Agent payload 和模型上下文上限。当前代码有 131,072-byte Agent payload 合同及 50,000-token 工具业务结果预算，知识库应适配预算而非静默截断。 |
| NFR-03 | 上传、待确认、读取、共享和清理状态可观察；日志记录状态、耗时、数量等必要信息，不记录正文或凭据。 |
| NFR-04 | 文献库持久跨会话可用，刷新和服务重启不丢失已确认文献、审核草稿、共享关系与会话选库偏好。 |
| NFR-05 | 在每库几百篇的目标规模下，用真实育种文献与问题验证选库、选文献、完整阅读和引用质量，并记录延迟、模型调用量及 token 消耗；不得未经实测承诺准确率或性能数字。 |

| AC-07 | 同库重复 | 同名、异名、同批、重试与并发上传相同字节均只保留一个有效文献或草稿。 | FR-05 |

| AC-09 | 跨库独立 | 同文献进入两个库后，在一个库修改、替换、删除不影响另一个库。 | FR-05、FR-07 |
| AC-10 | 正文替换 | 新正文经确认后成为唯一当前正文；旧正文、临时与受管副本清除，无历史正文下载。 | FR-06、FR-07 |
| AC-11 | 删除与恢复清理 | 删除后不能新读；注入文件清理失败及重启，状态不假成功，恢复后无残留受管全文。 | FR-07 |
| AC-12 | 索引完整与修复 | 索引含全部已入库文献；修改、替换、删除同步；注入索引写入失败不会读取过期索引。 | FR-09 |
| AC-13 | 共享对象 | 仅已有用户名可被授权；共享立即生效且重复请求不增加重复授权。 | FR-10 |

| AC-15 | 授权统一 | 未授权或撤权后，列表、索引、正文、下载及工具均不可新读。 | FR-11 |
| AC-16 | 团队接口预留 | 用主体解析器替身证明未来团队主体可经统一授权路径接入；当前 API 拒绝未支持的团队授权。 | FR-11 |
| AC-17 | 选库保存 | 默认全部可访问库；多选仅限这些库，刷新恢复，新会话回到自动模式。 | FR-12 |
| AC-18 | 固定本轮范围 | 运行中修改选择只影响下一轮；重试、重启恢复及结果复用不扩大原范围。 | FR-13 |
| AC-19 | 范围失效 | 部分失效则提示并使用剩余；全部失效要求重选，未读取其他库。 | FR-14 |
| AC-20 | 原生能力类型 | 工具发现、策略、执行、投影、观测识别 `knowledge`，不经过 Skill 或 MCP 包装。 | FR-15 |
| AC-21 | 实际查询链路 | 记录模型请求证明先获得索引，再实际读取选中文献正文，最终样例使用正文细节作答。 | FR-16 |
| AC-22 | 长文件与分页 | 覆盖超过一次工具结果预算的索引和正文，段落无遗漏且实际进入模型请求，不假报完整。 | FR-17、NFR-02 |
| AC-23 | 读取中内容变化 | 修改索引或正文后旧游标不会混读；旧正文引用不能复活旧文件或冒充新文件。 | FR-17 |

| AC-25 | 历史答案独立 | 更新、删除正文或撤销共享后，既有答案文本及其中引用不变；无答案关联复核或删除。 | FR-18 |
| AC-26 | 失败及并发 | 提取失败可重试或手工完善；并发编辑不丢更新，发布中断可恢复且无双重当前正文。 | FR-03、FR-06、FR-07 |
| AC-27 | 完整交付回归 | SQLite/PostgreSQL、启用的 Runtime Sidecar 路径、前端类型与构建、既有 Skill/MCP/普通聊天均通过适用检查；真实文献评测报告记录结果。 | 第 9 节、NFR-01 至 NFR-05 |
| AC-28 | 新读取与结果复用 | 在同一 AgentRun 中，先成功读取索引或正文，再修改索引或替换正文；以原参数（无分页游标）重读应得到当前修订号或 SHA-256 及对应内容；撤权或删除后相同读取明确返回不可用，不能复用旧成功结果。 | FR-11、FR-13、FR-15、FR-17 |
| AC-29 | 压缩后的全文证据 | 构造必须触发上下文压缩的多段索引和长文；检查压缩模型实际请求包含待压缩段落而非仅有引用，并按实际内容计数；最终回答能正确使用仅存在于压缩所覆盖的前段正文中的细节，并标注对应文献。 | FR-16、FR-17、FR-18、NFR-02 |

## 12. 仓库接入依据与技术选择

以下是成文时核对的仓库事实，不表示知识库已经实现：

| 当前入口 | 接入影响 |
|---|---|
| `src/orchestration/models.py`、`registry.py` | 已有能力描述与注册，需明确支持独立 `knowledge` 类型。 |
| `src/orchestration/agent_loop/tool_catalog.py` | 当前只向模型开放 Skill 与 `mcp.dispatch`，必须补齐知识库发现与调用策略。 |
| `src/orchestration/composite_executor.py` | 复用通用执行器组合，增加知识库执行器。 |
| `src/orchestration/agent_loop/result_projection.py`、`capability_invoker.py`、`context.py` | 需增加独立知识库结果合同、正文按需载入及正确的能力分类，不能落入旧 Skill 结果分支；新读取不能被同参成功结果复用跳过当前范围、授权及资源状态校验。 |
| `src/orchestration/agent_loop/compaction.py` | 压缩请求需展开知识库索引或正文引用、按实际内容计数，并保留后续作答所需的文献事实与标识，不能只压缩引用信息。 |
| `src/storage/conversation_files.py` | 可借鉴描述与 Markdown 索引生成模式；文献库使用独立、跨会话的资源与权限生命周期。 |
| `src/storage/sqlalchemy_models.py`、`sqlite/`、`postgres/` | 复用共享模型和仓库模式，增加库、文献、草稿、授权及会话选库数据。 |
| `frontend/src/App.tsx` | 当前账户设置按钮直接打开 MCP 设置，需增加文献库管理入口及会话选库控件。 |

技术选择依据是已确认的目录检索流程、Markdown 输入和现有基础设施，不是准确率跑分结论。LlamaIndex 和 PageIndex 的检索思想可作为研究参照，但本次不增加其依赖或另建其运行体系。
