# 18-02 前端恢复体验 PRD

- **项目**：breeding_agent
- **范围**：前端任务恢复、SSE 重连、artifact retry、上传缺失提示
- **文档状态**：分步 PRD（继承总纲 PRD 18）
- **日期**：2026-05-24
- **上游总纲**：`docs/prd/backend/18-失败自检恢复与Fallback控制层PRD.md`

## 1. 背景

后端已持久化任务事件并支持 replay，前端也已有事件去重和 current task 刷新恢复。但事件流断开后，前端目前主要做一次任务状态查询；若任务仍在运行，缺少持续重连。任务完成后 artifact 加载失败也缺少明确 retry 入口。上传 ID 缺失会被后端收集，但用户缺少明确提示。

## 2. 目标

- SSE 断开且任务仍 active 时自动重连。
- 复用后端 replay 和前端 event id 去重，避免重复渲染。
- artifact 加载失败后保留 task id 和 retry 入口。
- 普通任务上传缺失显示 warning，但任务可继续。
- 显式文件类 Skill 缺 required upload 时 fail early。
- 跨账号 upload 继续权限拒绝，不进入 fallback。

## 3. 非目标

- 不新增后端 task snapshot API。
- 不把 warning 写入正式 assistant 历史正文。
- 不重新执行已完成任务来恢复 artifact。
- 不改变账号隔离和上传权限策略。

## 4. 功能需求

| ID | 需求 | 默认行为 |
|---|---|---|
| FR-02-1 | 事件流错误后查询 task status | 启用 |
| FR-02-2 | task active 时进入 reconnecting 并指数退避重连 | 启用 |
| FR-02-3 | task terminal 时停止重连并按终态处理 | 启用 |
| FR-02-4 | 状态查询失败不得误标失败 | 启用 |
| FR-02-5 | artifact 加载失败展示 retry 按钮 | 启用 |
| FR-02-6 | artifact retry 成功后替换当前气泡内容 | 启用 |
| FR-02-7 | 普通任务 upload missing 显示前端 warning | 启用 |
| FR-02-8 | 显式文件类 Skill required upload missing fail early | 启用 |

## 5. SSE 重连契约

- 初始延迟：500ms。
- 最大延迟：5000ms。
- 倍数：2。
- 最大连续重连次数：不限，但仅在任务 active 时继续。
- 重连后必须使用同一 task events endpoint，让后端 replay 补齐断线期间事件。
- 前端必须按 event id 去重。

UI 文案：

```text
连接中断，正在恢复任务进度……
```

## 6. Artifact retry 契约

任务 completed 后 artifact 加载失败时：

- task phase 可视为 completed。
- assistant message 进入 result_load_failed 展示状态。
- message 保留 task id。
- 展示“重新加载结果”。
- retry 只拉取 artifact，不创建新任务，不写新用户消息。

UI 文案：

```text
任务已完成，但结果加载失败。
```

## 7. Upload warning / fail early 契约

普通任务：

- missing upload ids 不暴露原始 id、路径或 storage key。
- 发出 `upload.warning` 前端可见事件。
- 任务继续执行，只注入已解析 artifact。

事件 payload：

```json
{
  "code": "upload_missing",
  "missing_count": 1,
  "message": "有附件未找到或已失效，本次任务未包含该附件。"
}
```

显式文件类 Skill：

- required upload 缺失时请求 fail early。
- 不创建长任务。
- 前端提示重新上传文件。

跨账号 / 越权 upload：

- 直接权限拒绝。
- 不进入 warning fallback。
- 记录安全审计。

## 8. 状态模型

前端新增或明确以下展示状态：

| 状态 | 含义 | 是否写入历史正文 |
|---|---|---|
| reconnecting | 事件流断开，任务仍 active，正在恢复订阅 | 否 |
| result_load_failed | 任务完成但 artifact 加载失败 | 否 |
| upload_warning | 附件缺失但任务继续 | 否 |

## 9. 验收标准

- SSE 断开且 active task 自动重连。
- replay 事件不重复渲染。
- 状态查询失败不误判失败。
- SSE 断开时 task completed，前端停止重连并加载 artifact。
- artifact 首次失败后显示 retry 按钮。
- artifact retry 成功后替换气泡内容。
- 普通任务 upload missing 显示 warning 且任务继续。
- 显式文件类 Skill 缺 required upload fail early。
- 跨账号 upload 被权限拒绝。
- warning 不进入正式历史消息正文。

## 10. 测试要求

- `frontend/src/domain/taskEvents*` 覆盖 reconnecting/result_load_failed/upload_warning 状态。
- `frontend/src/App*` 覆盖 SSE error -> active -> resubscribe、artifact retry、upload warning。
- `tests/api` 覆盖 upload warning event 与文件类 Skill fail early API 契约。
- e2e 覆盖刷新 / 断线 / replay / artifact retry 的完整路径。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 重连造成事件重复 | 强制 event id 去重 |
| 网络长期不可用导致 UI 僵持 | reconnecting 文案保持用户可理解，取消按钮仍可用 |
| warning 被用户忽略 | 文件类能力 fail early；普通任务展示明确附件未包含文案 |
