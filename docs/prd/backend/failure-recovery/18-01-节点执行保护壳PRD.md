# 18-01 节点执行保护壳 PRD

- **项目**：breeding_agent
- **范围**：后端 orchestration 节点执行可靠性
- **文档状态**：分步 PRD（继承总纲 PRD 18）
- **日期**：2026-05-24
- **上游总纲**：`docs/prd/backend/18-失败自检恢复与Fallback控制层PRD.md`

## 1. 背景

当前节点模型已有 `retry_policy` 和 `timeout_policy` 字段，任务执行外层也能把未处理异常收束为 task failed。但节点执行边界异常仍可能绕过 node failed、completion policy 和 replan 链路，导致可归属节点失败直接变成任务级 crash。

本 PRD 要求新增统一节点执行保护壳，让可归属节点异常、可重试错误和超时都进入节点状态与事件体系。

## 2. 目标

- 所有可归属节点异常必须优先转成 `node.failed`。
- `retry_policy` / `timeout_policy` 必须由执行层统一消费。
- 可重试错误必须按有上限 attempt 执行。
- retry 必须尊重取消状态。
- attempt 过程必须有 audit-only 证据。
- node failed 后必须复用现有 completion / replan 机制。

## 3. 非目标

- 不重写 orchestration 为事件驱动架构。
- 不改变各 capability 的业务语义。
- 不默认为所有节点开启多次 retry。
- 不把安全、权限、schema、contract、enforce 失败转成成功。
- 不用节点 retry 包裹核心状态持久化失败。

## 4. 功能需求

| ID | 需求 | 默认行为 |
|---|---|---|
| FR-01-1 | 所有节点执行必须经过统一保护壳 | 启用 |
| FR-01-2 | 能力返回 `retriable=True` 且 retry 策略允许时，保护壳必须重试 | 默认 `max_attempts=1`，不额外重试 |
| FR-01-3 | 能力返回 `retriable=False` 时不得重试 | 启用 |
| FR-01-4 | 能力返回 interrupt / waiting input 时不得重试，不得 replan | 启用 |
| FR-01-5 | 调度器无可用实例、执行器抛异常、能力未捕获异常必须转为节点失败，除非属于系统级不可归属异常 | 启用 |
| FR-01-6 | timeout 以单次 attempt 为初始语义 | 启用 |
| FR-01-7 | retry backoff 前必须检查任务是否 cancelling / cancelled | 启用 |
| FR-01-8 | late result 在取消后必须丢弃并审计 | 复用现有 late-result discard 语义 |

## 5. 节点失败分类

| 分类 | 示例 | 行为 |
|---|---|---|
| 可重试业务失败 | provider transient、MCP transient、DB transient、能力返回 retriable | 未超上限则 retry，耗尽后 node failed |
| 不可重试业务失败 | 安全拒绝、权限拒绝、schema 错误、能力返回 non-retriable | 直接 node failed |
| 等待用户输入 | interrupt、Skill 缺必需输入、SQLQuery 需要澄清 | node waiting_for_input，不 retry |
| 执行边界异常 | 无实例、执行器异常、能力未捕获异常 | 可归属则 node failed |
| 系统级不可归属异常 | 核心状态读取/持久化失败、状态机严重不一致 | 保留 task-level crash 收束 |

## 6. 策略契约

### 6.1 Retry policy

```yaml
max_attempts: 1
initial_backoff_ms: 500
max_backoff_ms: 5000
backoff_multiplier: 2
jitter_percent: 20
retry_on: []
```

`max_attempts` 包含第一次执行。缺配置时等价于 `max_attempts=1`。

### 6.2 Timeout policy

```yaml
seconds: 60
```

初始只定义单次 attempt timeout；overall timeout 不在本步骤强制实现。

## 7. 事件与审计

前端事件保持高层：

- `node.started`
- `node.completed`
- `node.failed`
- `node.waiting_for_input`

新增或强化 audit-only：

- `node.attempt_started`
- `node.attempt_failed`
- `node.retry_scheduled`
- `node.timeout`
- `node.retry_exhausted`

审计字段必须脱敏，至少包含 node id、capability id、attempt、max attempts、error code、error category、duration、next backoff、cancellation observed。

## 8. 与其他步骤的边界

- 前端 reconnect 不依赖本步骤完成，但会消费更准确的 node failed / task failed 事件。
- RuntimeSidecar bounded retry 不由节点保护壳负责。
- LLM provider fallback 默认关闭；主代理 LLM transient 可作为普通 retriable 错误进入节点策略。

## 9. 验收标准

- 能力抛异常后节点失败，而不是任务直接 crash。
- 无可用实例后节点失败，而不是任务直接 crash。
- retriable 第一次失败、第二次成功。
- retriable 耗尽后节点失败并记录 retry exhausted。
- non-retriable 不重试。
- timeout 后节点失败。
- waiting input 不重试。
- cancellation during backoff 停止 retry。
- late result discarded。
- node failed 后现有 replan 逻辑能接管。

## 10. 测试要求

- `tests/orchestration` 覆盖保护壳、retry、timeout、replan 接入。
- `tests/api` 覆盖 task-level crash 与 node failed 的用户可见事件差异。
- `tests/lifecycle` 覆盖取消中停止 retry。
- fake capability 必须覆盖 success、retriable error、non-retriable error、interrupt、timeout、exception。

## 11. 风险与缓解

| 风险 | 缓解 |
|---|---|
| retry 造成重复外部调用 | 默认 `max_attempts=1`，只给显式安全可重试能力打开 |
| timeout 误杀长任务 | 继承已有 timeout_policy；MCP 长任务优先使用自身 durable task 机制 |
| 状态写失败被误当节点失败 | 核心持久化失败保持系统级 crash，不进入节点 retry |
