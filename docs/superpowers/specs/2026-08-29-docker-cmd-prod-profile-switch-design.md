# docker_cmd 本地生产 Profile 切换设计

## 目标

将根目录受保护的 `docker_cmd.md` 从当前 `main` 开发环境内容切换为生产环境内容，同时保证文件始终存在、权限不高于 `0600`、继续被 Git 忽略且未被跟踪，并且不在日志、补丁、提交或对话中暴露敏感值。

## 已确认现状

- 当前 Git 分支为 `main`；本任务不切换 Git 分支。
- 根目录 `docker_cmd.md` 当前是开发环境版本。
- 之前的切换方法是仓库外保存 `main`/`prod` 两份 `0600` profile，再使用 `install -m 600` 激活目标 profile。
- 之前位于临时目录的生产 profile 已不存在，不能直接恢复。
- 当前开发文件引用 `0.1.24` 开发别名；该版本只在本机完成构建，未推送或部署。最近有远端发布证据的生产镜像版本是 `0.1.23`。

## 方案

采用已批准的方案 A：以当前开发文件为结构基线，机械生成新的生产 profile。

1. 在仓库外新建权限为 `0700` 的临时备份目录，并用 `install -m 600` 保存切换前的完整文件。
2. 只修改已知环境字段：镜像仓库别名与已发布生产标签、容器名、Docker 网络、宿主端口、`MAF_ENV`、数据库目标、认证 secret 文件、runtime volume 和生产 Skill 挂载目标。
3. PostgreSQL 生产凭据只从现有本地 ignored 配置中提取并写入目标文件；不输出、不写入补丁、不创建 tracked 中间文件。
4. 使用原文件同目录的 `0600` 临时文件完成全部转换和校验，再以同文件系统原子 rename 激活；转换或校验失败时保留原文件不变。
5. 不执行 Docker 命令，不启动、停止、删除或部署任何容器，也不修改外部服务。

## 验收

- 根文件存在、非空且权限为 `0600`。
- 仅包含 production 环境标记，不残留 development/dev 环境标记。
- backend/frontend 使用最近已发布的生产镜像 `0.1.23`。
- 生产容器、网络、端口、数据库、volume、认证文件和 Skill 挂载标记各自一致。
- Markdown 中的 shell 代码块通过 `bash -n`；错误输出不得包含命令正文。
- `git check-ignore docker_cmd.md` 成功，`git ls-files docker_cmd.md` 无结果，tracked 工作树无额外变化。
- 切换前备份仍存在、非空且权限为 `0600`，可用于完整回滚。

## 回滚

若任一验收失败，使用切换前备份通过 `install -m 600` 恢复根文件，再重复存在性、权限、哈希、ignored/untracked 检查。任何路径都不得删除根文件或备份。
