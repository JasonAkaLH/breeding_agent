# compat API 文档接入与交互优化

- 日期：2026-09-24
- 分支：compat（基于 0.1.23）
- 状态：用户已确认以下四项范围并授权实施。

## 已确认设计

1. 部署说明使用前端 41999、后端 41888、前端路径 /seedpilot/，同步 compat runtime volume 名称。
2. 基础地址根据当前文档 URL 自动识别：后端 /api-doc 使用当前 origin，代理 /seedpilot/api-doc 使用 origin + /seedpilot。离线打开采用 http://127.0.0.1:41888。手动输入有效 HTTP(S) 基础地址后，22 个 curl 示例及复制内容同步更新；无效地址明确提示，暂停复制调用模板。保留 token 与业务 ID 占位符，不发送业务请求。
3. 搜索覆盖接口名称、路径、方法、参数、说明及示例，忽略大小写并支持多个关键词共同匹配；分类筛选继续生效。
4. 每个接口的完整说明、参数表、请求及响应示例放入同一 details 元素。全部展开/收起控制完整详情；点击接口目录时展开目标详情。

沿用当前单 HTML 页面及视觉风格，保留接口协议、业务说明、OpenAPI 与更新日志的同源加载方式，无新增运行依赖。

## 实施计划及验收

1. 用独立 Node + jsdom 测试复现地址不联动、搜索遗漏、折叠不完整的问题。
2. 修改 docs/api/api-doc.html 的部署说明、details 结构和少量交互逻辑；更新 CHANGELOG.md，并检查目录索引是否需要调整。
3. 运行页面交互回归与现有开发文档/代理配置测试；检查后端直连、代理前缀、离线打开、无效地址、复制及折叠行为；浏览器查看桌面和窄屏效果，检查最终 diff。

## 方案自查

四项均对应用户确认的缺陷；不含待定项。页面上的示例基础地址与文档资源地址各自用途明确，编辑示例地址不会改变 OpenAPI/更新日志来源。服务器上线需要后续把更新后的文档部署到 backend 镜像。
