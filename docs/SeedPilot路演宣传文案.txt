SeedPilot 智慧育种 Agent 路演宣传文案

开场介绍
SeedPilot 是一个面向农业育种场景的智能助手。育种家可以用自然语言提出问题，系统再去完成数据查询、资料整理、分析辅助和结果汇总。

它适合放在企业已有的育种系统旁边使用。原来的数据、文件和业务流程不用推倒重建，SeedPilot 更像一个新的智能入口，帮助团队把已有资料用得更顺手。

客户现在遇到的问题
很多育种团队并不缺数据，真正的问题是数据太分散、调用太麻烦。品种信息在一个系统里，田间记录在另一个系统里，试验结果可能还在表格、图片或历史报告中。

育种家要完成一个判断，往往要先找数据，再筛条件，再做对比，最后整理成报告。这个过程耗时，也依赖熟悉系统的老员工。新人想快速理解材料、性状和历史试验结果，也需要很长时间。

SeedPilot 想解决的就是这类日常工作负担。它不替代育种专家的判断，而是把查找、整理、初步分析和文字汇总这些环节变得更快。

能力一：用对话完成育种工作
用户不需要记复杂菜单，也不需要知道数据放在哪张表里。可以直接问：

"帮我查一下这个品种近几年的田间表现。"
"把这批材料按目标性状做个对比。"
"根据这些试验结果整理一份总结。"
"帮我看看高产抗病方向下一步可以怎么分析。"

SeedPilot 会根据问题判断该查什么、该调用什么能力，并把结果整理成用户能看懂的回答。

能力二：连接已有育种数据
SeedPilot 可以围绕客户现有系统接入数据资源，例如品种信息、性状数据、试验记录、田间记录、文件资料和历史报告。

对客户来说，价值在于不用换掉原系统。SeedPilot 把原来分散的数据串起来，让育种人员可以通过一个入口使用它们。

能力三：把复杂任务拆成连续流程
育种问题通常不是一步完成的。一个问题可能先要查品种，再筛材料，再做对比，最后形成结论。

SeedPilot 可以把这些步骤串起来。用户看到的是一个连续的任务过程，不需要在多个系统和工具之间反复切换。

能力四：沉淀专业育种能力
SeedPilot 可以按业务场景配置不同能力包，例如数据查询、OCR 识别、田间分析、田间设计、群体遗传分析、病害识别和知识导航。

这些能力可以逐步建设。客户可以先从最常用、最费时间的场景开始，再按作物类型、团队流程和业务重点继续扩展。

能力五：辅助分析和报告整理
SeedPilot 可以把查询结果、历史材料和分析过程整理成清楚的文字。它可以帮助育种家形成阶段总结、材料对比、试验说明、问题分析和汇报初稿。

这类工作过去经常占用专家大量时间。SeedPilot 可以先完成基础整理，专家再做判断、修订和确认。

能力六：信息不完整时主动追问
真实业务里，用户一开始经常说不全条件。SeedPilot 可以继续追问，比如作物类型、目标性状、试验地点、时间范围、文件材料或筛选条件。

这样可以把一个模糊问题逐步变成可执行任务，减少来回沟通和无效查询。

能力七：企业级安全治理
育种数据通常涉及企业核心资产。SeedPilot 支持权限控制、操作审计、数据访问边界和安全治理。

不同角色可以使用不同范围的能力。管理者也可以追踪系统做过什么、查过什么、输出过什么。这样 AI 能力可以在可管理的范围内使用。

SeedPilot 的架构分工
如果从使用过程看，SeedPilot 可以分成六层。每一层都对应一个清楚的职责，从用户入口一直到数据、工具和安全治理。

第一层是访问入口。育种家在这里提问、上传文件、查看结果，也可以看到任务执行进度。前端业务对话台、浏览器页面、接口文档、文件上传和消息流都属于这一层。客户真正接触 SeedPilot，首先接触的就是这一层。

第二层是 API 服务层。它负责接收请求，处理登录、会话、任务、上传和能力列表。可以把它理解成系统的服务窗口：用户的每一次提问、上传和查看结果，都会先经过这里。

第三层是 Agent 编排核心。这里负责理解用户想做什么，并把一个问题拆成可执行的步骤。比如先查数据，再筛选材料，再生成总结，或者在结果不完整时重新组织流程。它对应图里的 WorkflowRouter、LLM Planner、Scheduler 和 Memory 等模块。对用户来说，这一层让系统不只是回答问题，而是能组织一段完整的工作。

第四层是能力运行时。这里是真正干活的地方，包括主代理问答、Skill 能力包、MCP 工具能力、补槽、中断和取消。用户问一个育种问题，系统可能会调用数据查询，也可能调用 OCR、田间分析、群体遗传分析或知识导航。条件不够时，它还能继续追问，把问题补完整后再执行。

第五层是数据与外部资源。这里连接状态库、任务消息、文件资料、LLM 能力、MySQL 只读数据和外部工具服务。这一层让 SeedPilot 能用上企业已有数据和外部分析能力。也正因为有这一层，SeedPilot 不是一个孤立聊天框，而是可以接入真实业务资料的育种助手。

第六层是 Native 和部署底座。它负责系统运行、任务存储、沙箱隔离、工具运行和安全内核。客户平时不需要感知这一层，但它决定系统能不能稳定运行，能不能安全接入企业环境，能不能支撑后续扩展。

安全治理贯穿所有层。认证授权、审计脱敏和访问边界不是单独某个按钮，而是贯穿用户登录、任务执行、数据访问和结果输出的全过程。这一点对育种数据尤其重要，因为这些数据往往是企业长期积累下来的核心资产。

给育种家带来的变化
1. 查数据更快。育种家可以直接提问，不用在多个系统里反复找。
2. 分析更顺。查询、筛选、对比和总结可以连在一个任务里完成。
3. 材料整理更省时间。试验总结、材料对比和汇报初稿可以先由系统生成。
4. 新人上手更容易。新人可以通过对话了解历史数据、材料情况和业务流程。
5. 专家经验更容易复用。历史报告、分析过程和常用判断方式可以逐步沉淀。
6. 数据使用更可控。权限、审计和访问边界让企业更放心地使用 AI。

适合哪些客户场景
SeedPilot 适合已经积累育种数据、但数据使用效率还不够高的团队。比如种业企业、科研育种团队、区域试验管理单位，以及需要把品种、性状、试验和报告统一管理的业务部门。

它也适合从一个小场景开始落地，比如先做育种数据查询、田间报告整理或材料对比分析。等团队用顺了，再扩展到更多作物和更多业务流程。

客户价值总结
SeedPilot 的价值不在于多一个聊天窗口，而在于给育种业务增加一个智能工作入口。

对育种家来说，它减少重复查询和整理工作。对团队管理者来说，它提高数据使用效率，让经验和流程更容易沉淀。对企业来说，它可以在不推翻现有系统的前提下，把 AI 能力逐步放进日常育种工作。

结束话术
SeedPilot 希望做育种家的日常助手：能查数据，能连流程，能整理结果，也能随着客户业务持续扩展。

未来的智慧育种，不只是拥有更多数据，还要让数据更容易被使用，让专家经验更容易传承，让团队把更多时间放在真正的育种判断上。
