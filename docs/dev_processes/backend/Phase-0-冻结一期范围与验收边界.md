# Phase 0：冻结一期范围与验收边界

> 状态：已完成（2026-04-23）

## 目标
在任何代码实现前，先冻结“一期做什么、不做什么、验收到底怎么判”。避免后续把主框架内核、SQLQuery、API、长期记忆、生产化部署混成一次失控实现。

- 主 Owner：技术负责人 / 架构负责人
- 协作 Owner：后端主程、能力链路负责人、测试负责人

## 要做什么
- 明确一期交付对象是：**主代理最小内核 + SQLQuery 只读 MVP**。
- 明确主框架与 capability 边界：主框架只管编排、分发、状态、生命周期；SQLQuery 只管自身执行。
- 明确一期必须覆盖：
  - 核心共享模型
  - 状态存储抽象与 SQLite 本地实现
  - mailbox / interrupt / cancel / serial guard
  - 最小 DAG 编排与调度
  - 以**会话延续型记忆**为目标的记忆系统（服务同一账户下的会话连续性与上下文恢复；作为主框架状态存储的一部分，本地先落 SQLite）
  - SQLQuery 只读链路
  - FastAPI / SSE / cancel / query API
- 明确一期不做：
  - 人工审批
  - 权限控制
  - 通用工具调用平台
  - 多实例生产化部署
  - 完整长期记忆系统
  - 跨任务知识沉淀 / 任务知识复用型记忆
  - PostgreSQL 正式上线
- 冻结验收口径：
  - 能提交任务
  - 能观察状态和事件流
  - 能取消任务
  - 会话延续型记忆的最小字段集可被持久化并恢复
  - 能跑通 SQLQuery 只读链路
  - 能阻断危险 SQL

## 不做什么
- 不在本阶段写业务代码。
- 不在本阶段决定二期范围。
- 不在本阶段提前铺未来 capability 的工程壳子。
- 不把“后续可能需要”直接并入一期。

## 风险
- **范围漂移风险**：实现过程中顺手把长期记忆、跨任务知识沉淀、生产化部署、权限控制一起做进来。
- **边界塌陷风险**：把 SQLQuery 逻辑直接写进 orchestration。
- **验收失焦风险**：没有明确验收口径，最后只能凭感觉判断“差不多完成了”。
