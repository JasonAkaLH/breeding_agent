# 工作周报模板

## 使用场景

用于向老板或业务负责人汇报一周内的项目进展。重点不是罗列代码改动，而是把工作提炼成：

- 本周完成了什么阶段性成果；
- 这些成果对产品、工程能力或团队协作有什么价值；
- 当前项目推进到了什么状态；
- 下一步最关键的工作是什么。

## 写作原则

1. **按主题归类，不按日期流水账罗列。**
2. **标题先写结论，再展开事实。**
3. **每个主题控制在 3 ~ 5 个要点。**
4. **优先写可感知成果：可运行、可验收、可扩展、可交付。**
5. **技术细节服务于汇报目标，不展开过多实现细节。**
6. **可以保留一句总结性括号话，帮助老板快速理解当前阶段。**

## 推荐结构

```markdown
1. <项目 / 专题名称>完成<阶段性成果>，进入<当前状态>
  1. <成果事实 1：产品、架构或工程层面的进展>
  2. <成果事实 2：当前已经具备的能力>
  3. <成果事实 3：测试、验收或文档沉淀>
  4. <成果事实 4：对后续工作的意义>
2. <核心能力 / 业务链路>完成<关键接入或增强>
  1. <能力当前承担的角色>
  2. <链路包含哪些关键步骤>
  3. <相比之前的升级点>
  4. <稳定性、fallback、测试或可观测性补充>
3. 启动<下一阶段 / 新专题>，明确<设计方向或实施边界>
  1. <新专题的目标>
  2. <已经完成的设计或调研>
  3. <明确不做什么，避免边界膨胀>
  4. <下一步落地重点>
4. 对<方法论 / 工具 / 外部技术>进行了专项研究
  1. <研究方向 1>
  2. <研究方向 2>
  3. <形成的判断>
  4. <对项目下一步的帮助>

（<一句话总结：当前项目距离下一阶段核心目标还差什么，或本周最大结论是什么>）
```

## 可复用模版

1. `<项目名称>`完成`<阶段性成果>`，进入“`<当前状态>`”阶段。
  1. 完成`<项目 / 模块>`从`<起点>`到`<终点>`的落地，形成`<结构 / 链路 / 能力>`。
  2. `<项目名称>`目前已经具备`<关键能力>`，不再只是`<之前较弱或模拟的状态>`。
  3. 完成`<验收 / 测试 / 联调>`链路，包括`<关键验证项 1>`、`<关键验证项 2>`、`<关键验证项 3>`。
  4. 形成`<文档 / 规范 / 计划>`，为后续`<协作 / 扩展 / 交付>`提供基础。
2. 完成`<核心能力>`接入 / 增强，并启动`<专题名称>`。
  1. `<核心能力>`已作为`<项目名称>`的`<角色定位>`接入主链路。
  2. 当前链路包括：
    1. `<步骤 1>`
    2. `<步骤 2>`
    3. `<步骤 3>`
    4. `<步骤 4>`
  3. 将原本`<旧实现方式>`升级为`<新实现方式>`：
    1. `<升级点 1>`
    2. `<升级点 2>`
    3. `<fallback / 兼容策略>`
    4. `<测试策略>`
  4. 补齐`<可观测性 / 稳定性 / 配置 / 工程化>`设计，避免`<关键风险>`。
3. 启动`<下一阶段>`：`<下一阶段主题>`。
  1. 完成`<设计文档 / 技术调研 / 方案评估>`，明确后续要解决`<问题>`。
  2. 设计目标不是`<容易误解或不应做的事情>`，而是实现`<真正目标>`。
  3. 明确`<边界 1>`、`<边界 2>`、`<边界 3>`。
  4. 初步评估`<风险 / 兼容性 / 部署 / 性能>`，当前结论是`<判断>`。
4. 对`<工具 / 方法论 / 技术方向>`进行了专项研究。
  1. 梳理了如何`<规范行为 / 提升效率 / 降低风险>`。
  2. 研究了`<工具 A>` / `<工具 B>`的价值与边界。
  3. 形成了`<项目名称>`后续采用`<技术或方法>`的设计判断。
  4. 明确下一步重点：让`<项目名称>`从“`<当前状态>`”继续推进到“`<下一目标状态>`”。

（`<项目名称>`本周已经完成`<最大成果>`，下一阶段核心就是`<下一步最关键目标>`。）

## 填写提示

- 如果本周只有一个大主题，可以只写 2 ~ 3 个一级条目。
- 如果涉及技术债或风险，用“当前结论 / 当前限制 / 下一步补齐”表述，避免显得工作未完成。
- 如果是研发型项目，建议至少包含一条“验证 / 测试 / 文档沉淀”。
- 如果是探索型项目，建议突出“形成判断”和“明确边界”。
- 面向老板汇报时，优先使用“完成、打通、形成、明确、验证、进入下一阶段”等结果型动词。
